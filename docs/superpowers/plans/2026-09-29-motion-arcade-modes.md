# Motion Runner — план развития режимов

> Для исполнителя: выполнять этапы последовательно с помощью `executing-plans`; после каждого законченного изменения запускать относящиеся к нему проверки и делать отдельный настоящий коммит. Этот документ описывает целевое поведение, а не подтверждает готовность перечисленных режимов.

**Цель:** закончить удобную игру с камерой и расширить её до семи разных мини-игр с общей системой распознавания, конкретными исправлениями и готовыми лицензированными ассетами.

**Архитектура:** сохраняем Bun-монорепозиторий. Чистые распознаватели, правила и оценка находятся в `packages/game`; камера, Web Audio, Three.js и интерфейс — в `apps/web`. Один контроллер сессии управляет активным режимом, паузой и результатами.

**Стек:** существующие закреплённые версии TypeScript, Vite, MediaPipe Pose Landmarker, Three.js, Motion, postprocessing, three.quarks, Vitest и Playwright. Новая нейросеть, React и база данных для этих режимов не нужны.

## 2. Что уже есть и что необходимо исправить

Осмотрен репозиторий на базе коммита `3ff8c96`; поверх него есть незакоммиченные изменения. Их сохраняем, не откатываем и не включаем автоматически в чужие коммиты.

- `packages/game/src/core/game.ts`, `gesture.ts`, `session.ts`: основа Classic и общего сценария.
- `apps/web/src/vision/pose-tracker.ts`, `pose.worker.ts`: камера и распознавание.
- `apps/web/src/presentation/world.ts`, `characters.ts`, `character-picker.ts`: сцена и четыре KayKit-персонажа.
- Новые `environment.ts`, `route.ts`, `journey.css`: окружение и маршрут; используем существующий визуальный язык.
- Незакоммиченный `packages/game/src/core/modes.ts`: прототип восьми идентификаторов режимов, простых подсказок и счёта.
- Незакоммиченный `music-transport.ts`: синтезированная музыка на Web Audio. Это основа для тестирования транспорта, а не готовая синхронизация всех режимов.

По чтению текущего прототипа обнаружены конкретные проблемы:

1. В `ModeEngine.update` проверка истечения подсказки находится внутри окна её активности. Для Mirror/Blaster условие позднего пропуска недостижимо; для Rhythm оценка обрезается раньше заявленного окна. Необработанная первая подсказка может остановить очередь.
2. `MusicTransport.start` ставит следующий удар на `currentTime + 0.06`, округляя индекс удара. Возобновление посередине доли теряет её фазу.
3. Six-Seven начисляет повтор на смене руки: это половина требуемого полного цикла. Нет достаточной проверки амплитуды каждой руки.
4. Dance и Mirror пока сводятся к совпадению `lane/handsUp`; это не сравнение с эталонной позой или танцем.
5. Duo прибавляет одинаковые очки обоим при совместном совпадении; независимые оценки и стабильные идентификаторы ещё нужны.
6. Blaster проверяет боковое положение кисти, а не вход нужной кисти в конкретную мишень.

Сначала закрепляем эти случаи тестами. Не объявляем их исправленными только на основании этого плана.

## 3. Общий пользовательский сценарий

`Welcome → камера/модель → калибровка → выбор режима → короткая практика → готовность → отсчёт → игра → результат`.

Первый клик разрешает камеру и активирует звук. Персонажа можно выбрать перед этим кликом; после запуска камеры основные переходы доступны жестами:

- В меню наклон на 500 мс переключает карточку один раз. Следующее переключение требует 250 мс нейтрали.
- Обе руки вверх на 1 секунду подтверждают карточку; затем руки вниз и отсчёт 3 секунды.
- На результатах две карточки: `Play again` по умолчанию и `Choose mode`; те же жесты выбора и подтверждения.
- Смена режима сбрасывает его правила и tutorial, но сохраняет калибровку, если игрок и положение камеры не изменились. Смена игрока требует новой калибровки.
- В игровом состоянии жесты меню отключены. Ошибка разрешения камеры имеет обычную кнопку повторной попытки, поскольку камера ещё недоступна.

Калибровка: 2 секунды устойчиво стоять прямо с опущенными руками. Показать текущую причину ожидания: `Lower both hands`, `Keep your hips in view`, `Stand still for a moment`. Не оставлять просто неподвижные 0%.

Общие состояния сохраняем в `Stage`; экран выбора добавляем явно как `MODE_SELECT`. Для каждого режима задаём tutorial и профиль необходимых суставов. Classic/Rhythm — три исходных жеста. Mirror/Blaster/Six-Seven — собственная практика. Dance — проверка полного тела и короткая демонстрация.

Потеря необходимых суставов или кадр старше 300 мс, скрытие вкладки, остановка аудиоконтекста в музыкальном режиме → PAUSED. Одна секунда устойчивого трекинга, руки вниз, отсчёт → продолжение. Музыка, счёт, эталон и препятствия заморожены вместе. Уход камеры/ошибка worker переводят в восстановление с конкретным текстом.

```ts
import type { GameMode, GestureAnalysis } from '../core/types';

export type Action = 'LEAN_LEFT' | 'LEAN_RIGHT' | 'HANDS_UP_JUMP'
  | 'REACH_LEFT' | 'REACH_RIGHT';
export interface ActionEvent {
  id: number;
  playerId: string;
  action: Action;
  capturedAtMs: number;
  songTimeMs: number;
}
export interface Cue {
  id: string;
  atMs: number;
  action: Action;
  earlyMs: number;
  lateMs: number;
}
export interface ModeInput {
  nowMs: number;
  songTimeMs: number;
  pose: GestureAnalysis;
  events: readonly ActionEvent[];
  paused: boolean;
}
export interface RoundResult {
  mode: GameMode;
  score: number;
  cleared: number;
  misses: number;

}

  reset(): void;

}
```

`finish()` идемпотентен. `reset()` сбрасывает очередь, дедупликацию, комбо, намерения, pending-события и временные окна. Представление получает snapshot, но не меняет симуляцию. События несут последовательный ID: рендер одного результата позы много раз не начисляет очки повторно.

## 5. Распознавание и Error Mode

Пиксельные координаты: `x = landmark.x × frameWidth`, `y = landmark.y × frameHeight`. Нормализация по длине торса и ширине плеч; исключаем почти нулевой масштаб. Углы считаем между векторами, аргумент acos ограничиваем диапазоном [-1, 1]. Порог видимости необходимых суставов — 0.6, время сглаживания — 80 мс. У каждого режима свой список обязательных суставов.

Сохраняем исходную формулу lean и её знак; не зеркалим landmarks дважды. Названия рук означают анатомическую руку игрока. Координаты мишеней относятся к зеркальному preview. Фронтальный coach повторяет игрока как зеркало; соответствие левой/правой кости задаём одной таблицей и проверяем асимметричным fixture.

Наклон: активация 0.22, отпускание 0.12, подтверждение 120 мс. Прыжок: обе кисти выше глаз с запасом 0.20 длины торса на 100 мс, повтор только после опускания обеих кистей ниже плеч. Сохраняем одновременный наклон и прыжок в Classic. Набор активных распознавателей задаётся режимом: Six-Seven не вызывает игровой прыжок.

Приоритет обратной связи: кадрирование → конкретное отклонение ожидаемого движения → timing → успех. Одновременно одно исправление. Частичная попытка должна длиться 500 мс, повтор текста не чаще 2 секунд, исправленная ошибка снимается сразу. Нейтральное положение не является ошибкой. Miss или столкновение сами по себе не доказывают неправильный жест.

| Наблюдаемые данные | Сообщение | Подсветка |
|---|---|---|
| Неполный наклон в ожидаемую сторону | `Lean a little further left/right` | Плечи и таз |
| Подтверждённый наклон противоположного направления в tutorial | `Lean left/right instead` | Плечи |
| Одна рука достигла jump-цели, другая ниже | `Raise your right/left hand above your head` | Нужные локоть и кисть |
| Обе кисти подняты, но ниже цели | `Move both hands above your head` | Обе кисти |
| Эталон требует прямой руки, локоть устойчиво согнут | `Straighten your left/right arm` | Соответствующий локоть |
| Six-Seven: руки синхронно идут вверх/вниз | `Alternate your hands` | Обе кисти |
| Six-Seven: амплитуда недостаточна | `Move your left/right hand a little higher` | Нужная кисть |
| Подтверждённое правильное действие раньше timing-окна | `Wait for the beat` | Индикатор ритма |
| Необходимая кисть за кадром | `Keep your right/left hand in view` | Край preview |

## 6. Музыкальные часы и очередь

Основной источник музыкального времени — `AudioContext.currentTime`. Для Classic остаётся монотонное активное время симуляции. DOM-таймеры используются только для планирования звука с небольшим запасом, не для накопления игрового времени.

```text
songMs = savedOffsetMs + (audioCurrentTime - scheduledStartAudioTime) * 1000
cueMs = firstBeatMs + beatIndex * 60000 / bpm
eventErrorMs = frameSongTimeMs - cueMs
```

До scheduledStart возвращаем savedOffset, а не отрицательное время. Храним отображение main-thread performance-времени кадра в аудиовремя текущего сегмента воспроизведения. Worker возвращает исходный timestamp и sessionGeneration, не собственное время доставки. Смена раунда/пауза инвалидирует запоздавшие результаты. Задержку инференса второй раз из timestamp не вычитаем.

При pause фиксируем offset, прекращаем звук и расписание; при resume после отсчёта создаём новый AudioBufferSourceNode с тем же offset. Синтезатор также восстанавливает дробную фазу удара, а не начинает новую долю. Если аудио не запустилось, музыкальный раунд не движется молча. Измеряем рассогласование на ноутбуке; стартовые окна учитывают сглаживание, финальные пороги утверждаются камерной проверкой. Аппаратный audio/video offset — отдельная настройка, не постоянная «магическая» задержка worker.

Очередь сначала сопоставляет пришедшие свежие события по времени исходного кадра, затем закрывает просроченные cues. При одном кадре в обработке можно отложить закрытие cue до получения этого кадра, максимум на порог свежести 300 мс; при превышении — пауза, а не штраф за производительность. Одно событие поглощается максимум одной подсказкой; просроченные элементы проходят циклом, не оставляют очередь на первом Miss. Окна одной и той же команды не пересекаются.

После паузы показываем одну ознакомительную музыкальную меру без оценки, с замороженной позицией раунда; затем продолжаем ровно с сохранённого offset. Удаляем незавершённые кандидатные жесты, повторно требуем нейтраль и не доначисляем события, случившиеся в паузе.

## 7. Правила семи режимов

### Classic Run

Сохраняем 60 секунд production / 20 секунд dev. Первая волна на 5-й секунде, далее через 2.5 секунды. Предпросмотр минимум 2.5 секунды; +10 за пройденную волну, -5 за столкновение, минимум 0. Один расчёт на волну. Высокие препятствия обходятся, низкие можно перепрыгнуть. Прыжок 900 мс, безопасная часть 150–750 мс. Итог: очки, пройденные волны, столкновения, личный рекорд. Проверить существующий исправленный момент пересечения с позицией персонажа.

### Rhythm Run

Первый уровень: 60 секунд, 120 BPM у встроенного тестового трека, команды раз в 4 доли (2 секунды), первая на 4-й секунде. Последовательность LEFT → JUMP → RIGHT → JUMP повторяется. Рядом с командой явно показываем возврат в нейтраль. В финальном музыкальном файле темп и firstBeat берём из проверенной разметки; 120 не навязываем чужой записи.

Начальные окна: Perfect ±180 мс = 100 очков, Good ±360 мс = 75, вне окна = Miss и 0. Комбо увеличивается за попадание, сбрасывается при Miss; множитель очков в первой версии не нужен. Accuracy = набранные очки / (100 × число cues) × 100. Показать подсказку за 2 секунды и точку попадания. Держать наклон с предыдущей команды недостаточно. Повтор требует нового фронта жеста после отпускания.

Музыкальные знаки заменяют независимые Classic-волны: игрок не должен выбирать между требованием музыки и другим препятствием. Дорожка и персонаж остаются. Ошибка времени не вызывает физический штраф второй раз.

### Six-Seven Challenge

Свободный раунд 30 секунд; музыкальный вариант добавляется после свободного. Здесь «67» — чередование рук, не количество упражнений. Согнутые локти допускаются, ладони не оцениваем без отдельного hand-tracker.

Пусть `hLeft/hRight = (shoulderY - wristY) / torsoLength`, `d = hLeft - hRight`. Полюс A: d ≥ 0.30, B: d ≤ -0.30; подтверждение каждого 120 мс. Полный повтор: A → B → A либо B → A → B. Первый полюс только запускает цикл; следующая смена — половина; возвращение — один повтор. Следующий цикл использует последний полюс как начало.

Дополнительно каждая кисть должна пройти не менее 0.25 длины торса между полюсами; иначе движение одной рукой не засчитывается. Минимум 200 мс между полюсами, максимум 2 секунды; при превышении сбрасываем незаконченный цикл, не уже набранный счёт. Jitter, удержание, руки вместе и потеря кисти не дают повторов. 100 очков за полный цикл, итог показывает cycles и bestCombo. В музыкальной версии ожидаемые полюса идут раз в 2 доли; очки выдаются только за полный цикл, timing по худшему из двух переходов: 100/75/0.

### Mirror Challenge

Раунд 60 секунд: 8 заданий по 7.5 секунды. Первые 6 — LEFT, RIGHT, LEFT_HAND_UP, RIGHT_HAND_UP, BOTH_HANDS_UP, ARMS_OUT. Последние 2 — связки LEFT→RIGHT и LEFT_HAND_UP→RIGHT_HAND_UP.

Одиночная поза: демонстрация 1.5 с, окно попытки 5 с, результат 1 с. Связка: демонстрация 2 с, попытка 4.5 с, результат 1 с. Нужно удержать каждый элемент 500 мс; между элементами 200 мс нейтрали. Начальные допуски: угол ±20°, нормализованное положение кисти ±0.25 торса, lean по существующим порогам. 100 очков за задание; связка получает их только после обоих элементов в порядке. Музыка фоновая, попадание в beat не обязательно.

### Dance Party Solo

Один 60-секундный уровень из 8 фраз по 7.5 секунды. Простые фронтальные движения рук, наклоны и небольшие шаги; весь человек в кадре. Нужны реальные эталонные анимации, не только стрелки LEFT/RIGHT/JUMP.

Эталон снимается с окончательной анимации coach с учётом смешивания и отображается в той же системе признаков, что webcam. Начальные веса групп: руки 0.50, торс 0.25, ноги 0.25. Для каждого признака `similarity = clamp(1 - abs(player-reference)/tolerance, 0, 1)`; допуски хранятся по признаку, стартово 30° для угла и 0.35 торса для положения. Оценка фразы — 100 × (0.7 × poseSimilarity + 0.3 × timingSimilarity), округлённая до целого.

Фразу разрешено выровнять одним фиксированным сдвигом в пределах ±250 мс, шаг поиска 50 мс; timingSimilarity = max(0, 1 - abs(shift)/250). Нельзя независимо переставлять кадры или растягивать движение. Нужна валидная видимость всех обязательных групп минимум в 80% оцениваемых отсчётов; при нехватке данных — tracking recovery, а не оценка «плохой танец». Процент — игровое совпадение, не оценка здоровья или спортивной техники.

### Beat Blaster

60 секунд, одна мишень раз в 4 доли на начальной сложности. Игрок видит собственные кисти, цвет каждой руки и соответствующую цель. Координаты мишеней привязаны к откалиброванному корпусу в зеркальном preview; радиус 0.25 торса, комфортные позиции определяются пробными вытягиваниями рук. Не требуем точного удара в глубину.

Попадание — вход нужной кисти из-за внешней границы в круг в пределах ±360 мс. Начальные классы Perfect/Good совпадают с Rhythm. Для нового попадания кисть выходит за радиус 0.35 торса минимум на 150 мс. Вход, случившийся до появления мишени, не считается. Крупный провал между кадрами >150 мс не интерполируем как попадание. Сопоставление по времени исходного кадра и один ID мишени предотвращают повторный счёт. Kenney-модель и частицы отображают уже рассчитанное событие.

### Dodge Arena

60 секунд, 24 волны: первая на 4-й секунде, ещё 23 с интервалом 2.3 секунды. Видимость угрозы минимум 2 секунды. Первые 8 волн — одна опасная дорожка, следующие 8 — чередование одиночных и двойных, последние 8 — двойные с одной безопасной дорожкой. В первой версии только высокие угрозы и наклоны; приседания и новые прыжковые правила не нужны.

Для соседних волн проверяем достижимость безопасной дорожки при времени смены 500 мс и запасе реакции 750 мс. Считываем позицию на плоскости пересечения, не требуем повторного жеста, если игрок уже в безопасности. +10 за волну, -5 за столкновение, минимум 0; combo растёт при успехе и сбрасывается при попадании. Ни одного требования наклоняться физически за пределы устойчивой позиции.

### Dance Party Duo — после Solo

Две зоны, отдельная калибровка и независимые GestureEngine/score. PlayerTracker сопоставляет центры тазов с предыдущими траекториями и зонами, а не с индексом массива MediaPipe. Неоднозначное сопоставление, пересечение или исчезновение одного игрока приостанавливает обоих. Перемена мест вне первой версии. Оценка каждого независима; общий результат может показывать сумму, но не копирует очки одного другому. Требуются реальные два человека и отдельный замер производительности.

| [CMU Motion Capture](http://mocap.cs.cmu.edu/) | Короткие исходные танцевальные движения для ретаргетинга | Кандидат; сайт не ответил при этой проверке. Условия и выбранный файл подтвердить до включения |
| [AIST++](https://google.github.io/aistplusplus_dataset/) | Исследование структуры reference/music | Не поставляем данные с игрой. Права на аннотации, музыку и видео проверяются отдельно |

JustLMD и FineDance остаются исследовательскими ссылками из предложения, не источником разрешённых игровых файлов. Не включаем песни и записи Just Dance. Если CMU-фрагменты не подходят или права не подтверждены, Solo остаётся экспериментальным; не подменяем танец тремя стрелками.

Порядок добавления ассета:

1. Выбрать конкретные файлы и просмотреть/прослушать. Проверить лицензию в архиве и на странице автора.
2. В `apps/web/scripts/content-assets.mjs` фиксировать URL и SHA-256 выбранного архива/файла. Не использовать плавающий main как единственный идентификатор.
3. Поместить выбранные модели/текстуры в `apps/web/public/assets/blaster/`, музыку — в пакет уровня. Сохранить LICENSE и авторство; при CC BY показать автора также в игровых credits.
4. Дополнить `apps/web/public/assets/manifest.json` и `THIRD_PARTY_NOTICES.md`: источник, версия/хэш, автор, лицензия, изменения и конечный путь.
5. Подключить из `prepare-assets.mjs`; повторная сборка использует локальный файл и проверяет хэш. Ошибка загрузки не оставляет пустой «успешный» ассет.
6. Проверить модель в игре: масштаб, оси, прозрачность, тени, число материалов, отсутствие LFS-pointer вместо glTF. Загружать ассеты режима лениво; не грузить все танцы перед Classic.

Начальный бюджет нового 60-секундного уровня: музыка до 4 MB, дополнительные сжатые glTF/текстуры до 6 MB. Это бюджет добавки к существующей модели MediaPipe, не всего приложения. При превышении уменьшить текстуры/размер аудио до публикации. Визуальный эффект не должен скрывать руки или ближайшее препятствие.

Пакет `apps/web/public/content/<track-id>/`:

```text
track.json        — schemaVersion, id, title, durationMs, bpm, firstBeatMs,
                    chartVersion, audioFile, author, license, source
music.ogg         — выбранная и проверенная запись
chart.json        — cues с уникальными id, beatIndex, action и timing-окнами
coach.glb         — только у танцевального уровня
reference.json    — featureVersion, sampleRate, jointMap и признаки по времени
LICENSE.txt       — условия и атрибуция соответствующего контента
```

Тестовый встроенный синтезатор оформляется как отдельный уровень `pulse-120`, без фиктивного `music.ogg`; metadata содержит `audioKind: "synth"`. У файлового уровня `audioKind: "file"` и обязательный audioFile. Разметка хранит beatIndex, время вычисляется единым загрузчиком. Валидатор отклоняет отрицательные времена, повторные id, cues за концом трека и невозможные интервалы возврата.

Танцевальная подготовка: выбрать фронтальные mocap-фрагменты → перенести на KayKit Rig_Medium → исправить scale/оси/опору ног → собрать фразы под музыку → запечь итоговое смешивание → извлечь reference из того же результата → проверить человеком. Не предполагаем совместимость скелетов CMU и KayKit.

## 10. Проверки и готовность к сдаче

Обязательные unit-сценарии: neutral без corrections; зеркальные направления; разный масштаб/соотношение сторон; partial-жесты; нужная рука в тексте и highlight; rearm; удержание; jitter; 15/30/60 FPS; одновременный lean+jump; свежесть кадров; счёт один раз; точные границы timing; сброс после replay.

Обязательные браузерные сценарии: permission denied, camera unavailable, model failed; успешный start; скрытие вкладки; потеря и возврат тела; остановка звука; переходы режимов; localStorage недоступен; production-длительность; загрузка ресурсов из вложенного пути `/motion-runner/`; отсутствие сетевой отправки видео.

10 повторных раундов: один активный stream и worker, максимум один кадр inference в обработке, число AudioNodes/listeners/таймеров возвращается к исходному уровню, объекты Three.js не накапливаются. В тестах делаем наблюдаемыми счётчики ресурсов; не утверждаем отсутствие утечек только по визуальному осмотру.

Реальная приёмка: минимум два игрока разного роста, две дистанции, Chrome и Edge на демонстрационном ноутбуке. Для каждого включённого режима — полный раунд, намеренно неправильный жест, уход из кадра, возвращение, повтор без мыши. Автоматические fixtures помогают проверить код, но не заменяют эту приёмку.

## 11. Ближайшее действие

Начать с A и B: проверить актуальную рабочую копию, защитить Classic от регрессий и исправить завершение музыкальных подсказок. Затем C/D дают первый дополнительный законченный режим. Новый контент подключается по мере появления соответствующей сцены, с проверкой файлов и реальным коммитом каждого этапа.
